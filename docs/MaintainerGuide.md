# Maintainer Guide

> This guide is for project maintainers and collaborators of ResearchForge. It documents triage workflows, PR review checklists, maintainer SLAs, and contributor onboarding templates.

---

## Maintainer Responsiveness SLA

We maintain high responsiveness targets to keep contributors engaged:

| Task | Responsiveness Target |
|---|---|
| **Questions & Discussions** | 24 to 48 hours |
| **Issue Triage & Labeling** | 48 hours |
| **Pull Request Review** | 72 hours |

---

## Issue Assignment Policy

1. **Wait for comment requests:** Assign an issue only after a contributor comments asking to work on it.
2. **One issue per contributor:** Assign 1 issue at a time to keep opportunities open.
3. **7-Day Activity Window:** If an issue has no activity or draft PR after 7 days, unassign it politely:
   > *"Hi @username, we haven't seen an update on this issue in 7 days. We are releasing it so other contributors can pick it up. Thanks for your interest!"*

## First-Timer Welcome Template

When a new contributor opens their first PR, leave a warm welcome comment:

```markdown
Hi @username! 👋 

Thank you for opening your first pull request on ResearchForge for IEEE Summer of Code 2026! We're thrilled to have you here.

A maintainer will review your pull request within **72 hours**. In the meantime, feel free to check out [docs/Roadmap.md](../docs/Roadmap.md) to see what we're building next!
```

---

## PR Review Checklist

Before merging any PR, verify:
- [ ] PR template is completed.
- [ ] Commit messages follow Conventional Commits (`docs:`, `design:`, `feat:`, `fix:`).
- [ ] No broken internal links introduced.
- [ ] Added content aligns with current project stage (M0/M1 planning).
