## Documentation & Writing Standards

Since documentation, design, and architecture are the primary contribution types in M0/M1:

### Writing Style
- **Clear & Concise:** Write in plain, direct English.
- **Tone:** Welcoming, helpful, and professional.
- **Structure:** Use clear section headings (`#`, `##`, `###`).
- **Lists & Tables:** Use tables for structured comparisons and bullet lists for steps.

### Markdown Formatting
- Use ATX headings (`#`, `##`).
- Use fenced code blocks with language specifiers (` ```bash `, ` ```python `).
- Relative links for internal repository references (e.g. `[GettingStarted](GettingStarted.md)`).

## Git & Commit Standards

We follow **Conventional Commits**:
- `docs: improve vision statement formatting`
- `design: add project banner SVG`
- `feat: add semantic search endpoint`
- `fix: correct broken link in readme`
